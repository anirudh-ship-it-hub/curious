# Design Brief framework

Used per-screen/experience, not upfront. Rationale: AI coding agents implement functionality well but don't invent visual taste from a vague instruction ("make it beautiful") — this is true regardless of which agent is building, not specific to any one tool. Don't skip straight to code for any significant screen without running it through this.

Fill in at ~70-80% confidence, then prototype -> inspect -> learn -> refine. Don't let this become another form of procrastination.

1. **Experience** — calm/energetic? serious/playful? dense/spacious? editorial/tool-like? premium/utilitarian? focused/exploratory? -> Experience North Star (one sentence).
2. **Information architecture** — primary spaces, navigation, hierarchy of sections, one-click vs. deeper, persistent vs. hidden.
3. **Visual hierarchy** — what the eye notices first/second/third.
4. **Layout & spatial system** — nav placement, column structure, content width, whitespace, density, cards vs. open sections, responsive behavior.
5. **Visual language** — typography, color, spacing, shape, borders, shadows, icons, imagery.
6. **Components & interaction** — buttons, tabs, forms, search, edit mode, save state, modals, hover, expansion, loading, errors, confirmation.
7. **Motion & feedback** — motion explains state change, doesn't decorate.
8. **Responsive / accessibility / states** — desktop, mobile, tablet, keyboard, touch, contrast, focus, loading/empty/error states, long content, slow network, accessibility.

**References**: cite what you like + why + what NOT to copy (never "make it like Linear" — instead "I like Linear's nav hierarchy, not its visual treatment").
